## 安全评估

**总体评价：安全水平良好，核心安全机制完备。**

### ✅ 已做好的安全措施

1. **认证体系**：bcrypt 密码哈希（cost 12）、SHA-256 token 存储、30 天 TTL、每用户最多 10 个活跃 token
2. **登录防护**：per-IP 12次/分钟 + 全局 80次/分钟 限速、5 次失败后锁定 15 分钟、timing-safe 比较（dummy hash 防用户名枚举）
3. **CSRF 防护**：POST/DELETE/PUT 强制 Bearer header，拒绝 Cookie 认证
4. **SSRF 防护**：`safe_http.py` 实现 DNS 预解析 + IP 固定，拒绝私有/保留地址
5. **路径遍历防护**：`confine_to_root()` + `confine_to_user_root()` 严格限制文件访问范围
6. **CSP**：`script-src 'self'; object-src 'none'; frame-ancestors 'none'`
7. **绑定地址检查**：非 loopback 启动时强制要求多用户 + 管理员密码
8. **文件权限**：`users.json` / `sessions.json` 自动收紧到 0600
9. **Token 安全**：`is_safe_session_token()` 验证字符集后才写入 Set-Cookie
10. **危险调用控制**：核心服务路径未见 `eval`/`exec`/`subprocess`/`os.system` 等危险调用，无 SQL

### ⚠️ 当前风险点

| 级别 | 问题 | 说明 |
|------|------|------|
| 低 | CSP `style-src 'unsafe-inline'` | 降低了样式注入防护，但 `script-src 'self'` 仍有效 |
| 低 | 反向代理后 IP 限速失效 | `client_address[0]` 在代理后全变成 127.0.0.1；需配合代理层限速 |
| 低 | 部分文件写入非原子 | 2026-05-10 审计后已修复核心路径，但 `card_importer` 等仍有少量直接写入 |
| 信息 | `tmp/` 目录含较多测试数据 | 不影响安全，但占磁盘空间 |

## 架构观察

1. **无框架依赖**：后端用 stdlib `http.server`，前端原生 JS。优点是零供应链风险，缺点是手动实现路由/中间件/错误处理。
2. **文件系统即数据库**：所有状态存 JSON/JSONL/Markdown。适合单机自托管场景，但并发写入需要锁保护。
3. **多用户隔离**：每用户独立目录树 (`runtime-data/{user_id}/`)，路径遍历检查到位。
4. **LLM 调用链**：通过 `safe_http` 的 IP-pinned 连接调用外部 API，SSRF 防护完善。

## 建议优先级

1. **高**：清理异常吞没（至少在持久化/认证路径上加 logging）
2. **中**：拆分超大文件（`state_bridge.py` 等），提升可维护性
3. **中**：确认 `requests` 依赖是否需要；若不需要则移除
4. **低**：部署时配合反向代理做 IP 限速（Nginx `limit_req`）
5. **低**：清理 `__pycache__` 残留和 `tmp/` 大文件
