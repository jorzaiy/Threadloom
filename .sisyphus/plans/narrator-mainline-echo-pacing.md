# Narrator Mainline Echo Pacing Plan

## 背景

Threadloom 当前的 keeper / selector / state 连续性已经能稳定保留事实、物件、知情边界和主线线索。新增 `world-sim-drama` preset 后，单轮文本的 NPC 反馈和生活质感有所改善，但 `九幽大陆-20260517-443cb5` 仍主要依赖用户主动推动剧情：用户去码头、潜入仓库、偷盒、开盒、吃烤鱼，系统多数时候是稳定承接，而不是像 Tavern 样本那样主动制造可玩的事件入口。

对比 Tavern 样本：

- `tmp/九幽大陆 - 2025-10-2 @13h 38m 54s 886ms.jsonl`
- `tmp/九幽大陆 - 2026-02-24@23h32m24s881ms.jsonl`

它们的优势不是“每轮危机”，而是：

1. 系统会主动递出事件入口。
2. 用户决定是否升级、何时升级。
3. 强事件后有足够长的生活、关系、整理和余波。
4. 世界会回应玩家的小动作，但不总是惩罚、追查或揭露主角。

因此，下一步不应继续只调文风，也不应恢复旧版无约束主动推进，而应设计一个 **节奏感知 + 情绪配比的主线回响系统**。

## 目标

### 核心目标

让 narrator 不再只是等待用户推进，而是在合适节奏下主动让主线、NPC、物件、关系和场外世界产生回应；同时避免重新出现旧问题：剧情散、随机事件过多、全世界都在追主角、玩家没有喘息空间。

### 非目标

- 不重写 keeper。
- 不重写 selector。
- 不新增独立长期 planner 作为第一步。
- 不让 narrator 每轮都制造危机。
- 不把 Tavern 的显式 `<scene_direction>` / `<dice_results>` / `<handoff>` 标签输出到正文。
- 不让 NPC 默认看穿、审判、追捕或揭露主角。

## 问题诊断

### 1. 当前主线约束过度抑制 narrator 主动性

`backend/narrator_input.py` 中的当前事件目标、低压保护、旧线索轻触和反随机威胁规则有效防止了剧情发散，但也让 narrator 倾向于：

- 等用户明确追查线索。
- 不主动把闲逛、吃饭、等待、赶路拉回主线。
- 把旧线索放在 carryover 中，而不是变成场内可玩的入口。

结果是 `443cb5` 中用户推进很好，系统承接稳定，但系统本身的事件制造能力有限。

### 2. 不能把主动推进等同于危机推进

如果只加“低承诺动作必须回压主线”，会让世界显得危机重重：

- 差人总在查。
- NPC 总在怀疑。
- 物件总要暴露主角。
- 玩家每次吃饭、洗澡、闲逛都被主线打断。

这会破坏 Tavern 样本中很重要的轻松感、陪伴感和生活感。

### 3. Threadloom 需要的是“主线回响”，不是“主线追杀”

更合适的目标是：玩家做过的事、带着的物、认识的人、未解决的线索，在世界里产生回应。回应可以是：

- 机会
- 关系
- 奖励
- 好奇
- 支援
- 误会
- 小麻烦
- 轻压力
- 危险

危险只是其中一种，不应默认优先。

## 修改方向

### 方向一：新增 narrator 派生块“本轮节奏卡”

在 narrator prompt 中加入一个由现有 state / recent history / active threads / scene objective 派生出的非持久块。第一版不需要新 LLM，可用规则生成。

建议内容：

```text
【本轮节奏卡】
- 当前强度：Band 0/1/2/3/4
- 上轮/近几轮强度：...
- 冷却状态：冷却中 / 可推进
- 用户动作类型：低承诺 / 主线追查 / 高压行动 / 关系互动 / 休息整理
- 主线回响预算：0 / 0.5 / 1
- 推荐语气：生活 / 机会 / 关系 / 回报 / 好奇 / 支援 / 轻后果 / 压力 / 危险
- 可用回响材料：active thread、carryover clue、已登记 NPC、已登记物件、selector lore、NPC 关系、小善意记录
- 本轮禁止：无关新支线、无准备危机、默认揭露主角、默认惩罚主角、连续强压
```

作用：把“是否推进、推进多强、用什么情绪推进”显式告诉 narrator，而不是只给它抽象风格规则。

### 方向二：引入强度 Band

用于控制事件密度与危险程度。

| Band | 含义 | 允许内容 | 禁止倾向 |
|---|---|---|---|
| 0 | 喘息 / 生活 | 吃饭、洗澡、休息、购物、逗猫、闲聊、风景、关系余波 | 强危机、追捕、揭露 |
| 1 | 软 hook | 闲话、物件轻微反应、NPC 轻微注意、机会出现 | 强制行动、立刻惩罚 |
| 2 | 调查 / 社交压力 | NPC 试探、线索半露、交易条件、场外后果靠近 | 无准备战斗 |
| 3 | 主动危险 | 潜入边缘、追踪、阵法失控、妖物醒转 | 无关新危机 |
| 4 | 危机 | 战斗、逃跑、重大暴露、紧急救援 | 连续追加新危机 |

规则：除非用户主动冲进危险，否则每轮最多上升一个 Band。

### 方向三：引入主线回响预算

不是每轮都主动事件。

```text
0   = 只写喘息 / 余波 / 生活，不推主线。
0.5 = 只允许软回响，不改变局势。
1   = 允许一个绑定主线的主动事件入口。
```

例子：

- 用户刚偷盒逃出、开盒、调息后：预算多为 `0` 或 `0.5`。
- 用户连续几轮吃饭、闲逛、赶路：可提升到 `0.5` 或 `1`。
- 用户主动追查仓库、万宝楼、归渊底：预算可为 `1`。

### 方向四：强事件后设置冷却

强事件后必须有 aftermath，不要马上追加下一场危机。

建议规则：

- Band 3/4 后，默认 2-5 回合处于冷却。
- 冷却期允许：吃饭、洗澡、休息、疗伤、整理战利品、看书查资料、NPC 关系、生活小事、轻伏笔。
- 冷却期禁止：差人破门、杀手登场、盒子爆炸、新怪物袭击、连续追捕。

目标是学习 Tavern 2026 样本中“赵府事件后长时间晚饭、骑马、河边、烟花、计划”的余波结构。

### 方向五：主动事件的情绪配比

低压阶段不应默认选择压力或危险。事件 tone 应有配比。

建议 tone：

- `opportunity`：机会，例如有人提供门路、商机、线索入口。
- `relationship`：关系，例如 NPC 嘴硬关心、旁敲侧击、记住玩家小动作。
- `reward`：回报，例如玩家之前的小善意换来便利。
- `curiosity`：好奇，例如物件轻微反应、猫/火/水出现异常。
- `support`：支援，例如 NPC 帮忙遮掩、递符、给台阶。
- `light_consequence`：轻后果，例如太阳穴刺痛、符纸变黑、储物袋微凉。
- `pressure`：压力，例如差人打听、商会试探。
- `danger`：危险，例如追捕、暴露、战斗。

默认优先级：

```text
opportunity / relationship / reward / curiosity / support
> light_consequence
> pressure
> danger
```

### 方向六：保留低压行为的主体地位

当前规则“低压行为不要自动追加危险”应保留，但补充：

```text
低压行为不要自动升级成危险；但在回响预算允许时，可以加入一个非强制、可忽略、与 active thread 绑定的软回响。
```

示例：

- 不要：吃烤鱼时差人立刻抓人。
- 可以：猫对储物袋歪头；孙老头随口提一句后巷掌眼人；钟寡妇看见她带鱼回来，帮她闩上院门。

### 方向七：明确禁止“世界默认敌对”

新增规则应明确防止 narrator 总是选择对抗：

- 不要默认 NPC 看穿主角。
- 不要默认 NPC 盘问主角。
- 不要默认主角的小聪明失败。
- 不要默认物件暴露主角。
- 不要默认玩家每个异常动作都会引发惩罚。

允许：

- NPC 看出一点但不说破。
- NPC 误会成别的。
- NPC 自己也有秘密，所以不追问。
- NPC 因之前小善意提供帮助。
- 物件反而帮主角隐藏气息。
- 玩家小聪明确实暂时成功。

## 推荐第一阶段实验

### 实验范围

只改 narrator 输入侧，不改 keeper / selector 主逻辑。

优先文件：

- `backend/narrator_input.py`
- 可能新增一个小的节奏卡格式化函数
- `runtime-data/default-user/presets/world-sim-drama.json` 作为 A/B preset 继续保留

### 实验内容

1. 派生并注入 `【本轮节奏卡】`。
2. 在 drama preset 或 narrator final requirements 中补充：
   - 主线回响不等于危机。
   - 低压行为保留主体地位。
   - soft hook 可选、可忽略、不强制。
   - 优先正反馈与关系反馈。
3. 不新增独立 planner。
4. 不让 keeper 写入额外复杂结构，先观察 narrator 是否能用现有 state 产生更好的节奏。

### 手工验证样例

用 `九幽大陆-20260517-443cb5` 类似状态测试：

- 用户吃鱼、逗猫、闲逛时，是否出现轻量主线回响。
- 是否没有立刻变成抓捕或危机。
- 钟寡妇、孙老头、灰袍老者等 NPC 是否能提供关系、机会、支援或回报型事件。
- 连续 3-5 轮低压后，是否能自然出现一个更明确的主线入口。
- 强事件后是否能给足 2-5 轮喘息。

### 可执行 QA 流程

以下流程用于验证第一阶段实验是否真的改善节奏。执行前先备份目标 session，避免污染原始对照样本。

#### 0. 准备

1. 确认后端能启动：

   ```bash
   cd backend
   ./start.sh
   ```

2. 在 Web 设置中选择 `world-sim-drama` 或本实验专用 A/B preset。

3. 复制一个验证 session，建议从 `九幽大陆-20260517-443cb5` 派生，命名为临时验证 session，例如：

   ```text
   runtime-data/default-user/characters/九幽大陆/sessions/qa-mainline-echo-443cb5/
   ```

4. 加载该验证 session，确认当前状态大致处于：

   - 陆小环已经拿到铜盒 / 黄纸 / 归渊底线索。
   - 曾与钟寡妇、孙老头、灰袍老者产生互动。
   - 当前可进入低压生活段，例如吃鱼、回客栈、洗手、闲逛、休息。

#### 1. 低压软回响测试

输入：

```text
洗完手之后慢慢往回走，路过烤鱼摊，又买了一小包鱼干，打算带回去喂猫。
```

期望：

- 回复主体仍是低压生活：买鱼干、路边气味、摊主或猫的反应。
- 允许出现一个 soft hook，例如猫对储物袋/铜盒气息有轻微反应、孙老头随口说一句懂行门路、路人提到万宝楼。
- 不应出现：差人立刻抓捕、铜盒爆炸、杀手登场、强制追查。

判定：

- 通过：Band 0/1，主线只轻轻回响。
- 失败：直接升到 Band 3/4，或完全没有任何可玩回响。

#### 2. 关系 / 回报测试

输入：

```text
回到钟寡妇客栈，把刚买的鱼干放到灶房窗边，说：婶子，给猫的，别让它们偷锅里的。
```

期望：

- 钟寡妇应有关系型反馈：嘴硬、收下、不点破、提醒、帮忙遮掩、给台阶。
- 可轻触主线，例如她提到差人来过、旧仓库有人问话，但不能直接审问主角。
- 不应默认钟寡妇看穿、揭露、威胁或驱赶陆小环。

判定：

- 通过：玩家小善意得到正反馈或关系进展。
- 失败：NPC 只负责怀疑/盘问/揭露，或完全无视该小动作。

#### 3. 连续喘息保护测试

连续输入三轮：

```text
回屋把门掩上，先不碰那个盒子，烧水洗了把脸。
```

```text
把今天买来的东西都倒在桌上，慢慢整理，顺便看看还有几张符能用。
```

```text
有些困了，靠在床边眯一会儿，打算醒了再想万宝楼的事。
```

期望：

- 三轮中至少两轮保持 aftermath / 生活 / 整理状态。
- 可以有轻后果：太阳穴余痛、符纸变暗、储物袋微凉。
- 不应每轮都追加新危机。
- 第三轮末尾可以有 soft handoff，例如院外有人提到万宝楼、钟寡妇留饭、猫扒门，但不能强制打断休息。

判定：

- 通过：强事件后有喘息，且仍保留主线可见性。
- 失败：每轮都有差人/追兵/盒子爆发，或完全失去主线。

#### 4. 主动追查升级测试

输入：

```text
醒来以后，觉得还是得找个识货的人，出门去打听临江县有没有万宝楼或者懂行的掌眼人。
```

期望：

- 可以升到 Band 1/2。
- 系统应主动给一个明确但有界的入口：掌眼人、黑市后巷、灰袍老者再出现、商会旧招牌、本地小二提供消息。
- 事件应绑定已有线索：铜盒、归渊底、万宝楼、旧仓库、灰袍老者、钟寡妇人情。
- 不应突然开无关新支线。

判定：

- 通过：用户主动追查时，系统能提供清晰下一步。
- 失败：只写街景等用户继续问，或生成无关新危机。

#### 5. 对照样本记录

每轮记录：

```text
turn id:
user input:
observed band:
event budget used: 0 / 0.5 / 1
event tone: life / opportunity / relationship / reward / curiosity / support / light_consequence / pressure / danger
mainline anchor touched:
pass/fail:
notes:
```

至少跑 8-12 轮后与原 `443cb5` 同阶段对比：

- 是否更主动。
- 是否仍有喘息。
- 是否减少“全世界敌对”感。
- 是否让 NPC 关系和玩家小动作产生更多正反馈。
- 是否避免主线散掉。

## 验收标准

### 应该变好

- 系统不再完全等用户推进主线。
- 闲逛、吃饭、赶路、休息时，世界偶尔主动给机会或轻 hook。
- 玩家小动作更容易被正反馈接住。
- NPC 不只是怀疑或对抗，也能嘴硬关心、帮忙遮掩、给台阶、递机会。
- 强事件后有明确余波和喘息。

### 不能变坏

- 不能每轮都危机。
- 不能让世界显得全员敌对。
- 不能让主角总被揭露、盘问、惩罚。
- 不能开无关新支线。
- 不能削弱 keeper / selector 的事实连续性。
- 不能让 scene objective 失去主线约束作用。

## 待研究问题

1. 节奏卡应该在 `context_builder.py` 派生，还是在 `narrator_input.py` 根据 context 临时格式化？
2. Band / budget 是否需要持久化，还是可以从 recent history 纯规则估计？
3. 如何识别“用户正在享受喘息”，避免打断？
4. 如何从现有 active_threads 中挑 1-2 个最适合回响的材料，避免 thread 太多导致散？
5. 是否需要把“正反馈记录”从 NPC relationship / knowledge_records / recent history 中提取出来？
6. 如果第一阶段效果不足，是否再考虑轻量 planner 或 event clock？

## 当前建议结论

下一步设计方向应从“有界主动推进”进一步收敛为：

> **节奏感知 + 情绪配比的主线回响系统**

一句话目标：

> 不要让世界追杀玩家；让世界陪玩家玩，同时让主线在合适的时候自然回响。

## 补充分析：酒馆 Session 与 Sigon Preset 对比洞察（2026-05-17）

### 来源

- `tmp/九幽大陆 - 2026-02-24@23h32m24s881ms.jsonl`（1323 轮，LittleWhiteBox 插件 + 事件倒数系统）
- `tmp/九幽大陆 - 2025-10-2 @13h 38m 54s 886ms.jsonl`（1219 轮，scene_direction + handoff 系统）
- `tmp/Ny-Claude-Sigon-1.6.1-pro 内置Sigon智能分析引擎.json`（酒馆 preset）
- `九幽大陆-20260517-443cb5`（Threadloom 29 轮，glm-5.1）

### 核心发现：酒馆好玩的原因不是数值化节奏控制

对比后发现，酒馆 session 的"好玩"来自三个 Threadloom 完全缺失的结构性机制，而不是 Band/Budget 这类数值化控制：

#### 1. NPC 有独立人格和主动行为

酒馆 2026 中萧云铮不是"被触发才反应"的道具，而是一个有自己情感进度、动机和行为模式的活人：
- 他会主动献殷勤、主动紧张、主动犯蠢
- 他的反应基于自己的性格（少年气、羞涩、想表现）而不是"主线需要他做什么"
- 他会因为自己的原因做事（想给主角留好印象、想证明自己有用）

443cb5 中灰袍老者和钟寡妇只在被玩家触发时才有反应。他们没有"自己想做的事"。

#### 2. 每轮有隐式的"导演思考"

Sigon preset 的剧情 CoT 要求 AI 在输出正文前先做情景分析：
```
Current Situation / Actions of Each Character / Character Interaction
{{user}}'s Behavioral Language Analysis / Are there any implications?
Other Characters: Behavior Analysis / Personality Traits / Psychological Activities / Expected Reactions
Plot Development: Historical Plot Impact on the Present
```

这不是数值化的 Band/Budget，而是**每轮都让 AI 先想清楚"现在谁在做什么、为什么、接下来会怎样"**。

443cb5 的 narrator 没有这个思考步骤——它直接从 state + history 生成文本，缺少"导演意图"层。

#### 3. 强制创新 + 防重复机制

Sigon preset 用了三个独立模块（repeat-、repeat+、防重复）来确保：
- 不重复已出现的段落结构、句式、剧情、描写
- 角色不说重复的话
- 每轮输出必须在结构和内容上都是全新的

443cb5 的问题不只是"被动"，还有**每轮的写作模式趋同**——都是"环境描写 → NPC 反应 → 留一个 hook"的固定结构。

#### 4. 关系互动本身就是事件

酒馆 2026 中大量的"好玩"来自关系互动本身的戏剧性：
- 分战利品时的打趣和让来让去
- 帮忙整理仪容时的身体接触
- 幻心草中毒后的尴尬亲密
- NPC 犯蠢时主角的无奈和宠溺

这些不需要"主线回响"来驱动，关系线本身就有足够的可玩性。

#### 5. Handoff 机制：球在谁手里

酒馆 2025 有显式的 `<handoff>` 标签——每轮结束时明确"下一步该谁动"。443cb5 的 carryover_signals 是事实记录，不是叙事指令。

### 对 Plan 的修正方向

基于以上发现，Plan 的方向需要从"数值化节奏控制"转向"有机的叙事驱动"：

#### 修正一：用"导演 CoT"替代"节奏卡"

不要用 Band 0-4 / Budget 0-1 这种机械数值。改为在 narrator prompt 中加入一个轻量的思考引导：

```
【本轮导演意图】
- 用户刚做了什么？这个动作的潜台词是什么？
- 场上的 NPC 此刻在想什么？他们有没有自己想做的事？
- 上一轮的情绪是什么？这一轮应该延续、转折还是升级？
- 有没有已有的线索/物件/关系可以自然地产生反应？
- 这一轮结束时，球应该在谁手里？
```

这比 Band/Budget 更接近酒馆的实际工作方式——不是计算数值，而是**让 AI 先想清楚再写**。

#### 修正二：NPC 个人线驱动（新增方向八）

每个 locked/important NPC 应有隐式的"个人线状态"：

- **当前动机**：对主角的态度、自己的目标、自己的情绪
- **主动行为预算**：NPC 在场时，允许其基于动机做出不需要玩家触发的小动作
- **关系记忆**：记住玩家之前对他做过的事，并据此调整行为

实现方式：在 keeper 的 actor 数据中扩展一个 `motivation` 和 `disposition` 字段，narrator 根据它决定 NPC 是否主动做点什么。

示例：
- 钟寡妇记得主角买鱼干喂猫 → 下次主角回来时主动留了饭
- 灰袍老者对主角有好感 → 在集市上主动递一个消息
- 孙老头觉得主角有趣 → 主动找上门聊天

#### 修正三：Handoff 信号（新增方向九）

每轮结束时，keeper 应记录一个 `handoff_hint`：

```json
{
  "ball_holder": "npc_002",
  "hint": "她刚进灶房，但她注意到了主角带回来的东西",
  "next_beat": "relationship"
}
```

narrator 根据 handoff_hint 决定下一轮是否需要 NPC 主动行动。如果 ball_holder 是 NPC，即使用户只说"等着"，NPC 也应该有反应。

#### 修正四：防重复 / 强制创新（新增方向十）

在 narrator prompt 中加入轻量的防重复指令：

```
【创新要求】
- 不要重复上一轮的段落结构
- NPC 不要说和之前类似的话
- 如果上轮结尾是悬念，这轮换一种结尾方式
- 优先使用新的感官维度
```

#### 修正五：关系互动作为独立事件类型（强化方向五）

关系互动不应只是"主线回响"的一种 tone，而应该是**独立的事件驱动力**：

- 日常照顾、打趣/调侃、意外亲密、观念碰撞、小秘密、NPC 犯蠢

这些本身就是"事件"，不需要绑定主线也能产生可玩性。

#### 修正六：场景流动性（补充方向三）

引入"场景停留感知"——不是倒数计时器，而是世界自然流动的信号：
- 天色变化、人群散去、NPC 有事要走、新人物路过
- 不是强制跳转，而是"世界在动"

#### 修正七：Context 预算约束

443cb5 的 narrator prompt 已经 12-15k chars。任何新增内容必须极度精简。总新增 prompt 预算：不超过 300 chars。

### 修正后的实验优先级

1. **第一步**：在 narrator prompt 末尾加入轻量导演 CoT 引导（替代节奏卡）
2. **第二步**：在 keeper 的 actor 数据中加入 `motivation` 字段，narrator 据此让 NPC 主动行动
3. **第三步**：加入 handoff_hint，让 NPC 在"球在他手里"时主动做事
4. **第四步**：加入轻量防重复指令
5. **第五步**：观察效果，再决定是否需要 Band/Budget 数值化控制

### 待研究问题（更新）

1. 导演 CoT 是放在 system prompt 中让模型内部思考，还是作为显式的 thinking block 输出？（glm-5.1 是否支持 thinking？）
2. NPC motivation 应该由 keeper 每轮更新，还是由 narrator 自行推断？
3. Handoff hint 是否需要持久化，还是可以从 recent history 推断？
4. 防重复指令对 glm-5.1 的效果如何？是否需要更强的约束？
5. 如果导演 CoT 效果不足，是否考虑在 narrator 调用前加一个轻量的 planning LLM 调用？
6. 酒馆的"实时总结"机制是否值得借鉴？（Threadloom 已有 event_summaries，但格式不同）
7. 是否需要把"正反馈记录"从 NPC relationship / knowledge_records 中提取出来？

### 修正后的结论

下一步设计方向应从"数值化节奏控制"修正为：

> **导演意图驱动 + NPC 个人线 + 有机叙事流动**

一句话目标：

> 不要用数值管理节奏；让 AI 每轮先想清楚"谁想做什么"，然后让世界像活的一样自然流动。

核心原则：
- 酒馆好玩不是因为有 Band 0-4，而是因为 NPC 像活人、世界在流动、每轮都有新东西。
- 不要让世界追杀玩家；让世界陪玩家玩，同时让主线在合适的时候自然回响。
- 机械的数值控制是最后手段，有机的叙事驱动是第一选择。
